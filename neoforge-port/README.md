# Crop Genetics — NeoForge 1.21.1 port

**Development branch:** `feature/neoforge-1211-foundation`  
**Target:** Minecraft 1.21.1 / NeoForge 21.1.265 / Java 21  
**Temporary mod ID:** `cropgenetics`

This is the NEW codebase in `neoforge-port/`. The original Forge 1.18.2 root remains unchanged as the migration reference. This branch is **not a validated playable release**.

## Features currently implemented as source code
- Genetic genomes with dominant/recessive alleles, Growth/Gain/Strength and internal Fertility/Mutativity.
- Persistent genetic seed items via Data Components and crop-stick BlockEntity genome state.
- Crop sticks and double sticks: planting, server random tick growth, harvest products with Gain, offspring inheritance, simple mutation selection.
- Simple Vanilla/mod seed conversion using an unambiguous AgriPlants item ID mapping.
- Plant/environment requirements for explicit soil IDs/tags and light tolerance adjusted by Strength.
- Atomic crop datapack reload: one `CropDataReloadListener` prepares plant and mutation JSON from the same resource manager, preflights conflicting active species IDs before detailed validation, then publishes plants, mutations and unambiguous seed mappings via one immutable `AgriPlantsRegistry.Snapshot`. Validation and soil-tag diagnostics complete before a plant enters the candidate map, while `replaceAll` rejects inconsistent mutation references rather than silently removing them. Cross-breeding captures one snapshot per attempt. See `../temporary-research/ATOMIC_CROP_DATAPACK_RELOAD.md` and `../temporary-research/CROP_RELOAD_CONFLICT_TRANSACTION_AUDIT.md`.
- Per-resource datapack diagnostics: each loaded, disabled, invalid or conflicting plant/mutation file is recorded in an immutable `CropReloadReport`, published in the same snapshot. The server log summarizes totals and explains every skipped definition. See `../temporary-research/CROP_DATAPACK_DIAGNOSTICS.md`.
- Item/block reference checks: after parsing, `PlantRegistryValidator` verifies registered seed items, harvest products and explicit soil blocks. Unknown IDs disable the plant with a specific `INVALID` diagnostic; dependent mutations are skipped. A nonfatal `WARNING` reports missing `tags/block/<id>.json` source files for configured soil tags. The client visual loader separately warns about missing PNG resources without disabling the visual. Runtime tag membership and stitched atlas correctness are not yet verified. See `../temporary-research/CROP_REGISTRY_REFERENCE_VALIDATION.md` and `../temporary-research/SOIL_TAG_AND_CLIENT_TEXTURE_DIAGNOSTICS.md`.
- Static registry/reload audit: explicit seed/product items and soil blocks reject the special `minecraft:air` entry, and server resource discovery is scoped to exact crop data subfolders. Core 1.21.1 reload, block-property and atlas-render API signatures were also checked. See `../temporary-research/NEOFORGE_REGISTRY_RELOAD_STATIC_AUDIT_03.md`.
- Import safety limits: the AgriPlants parser and `PlantDefinition` restrict required mod/seed/stage/product lists to at most 64 entries, with stage values in 0..4096. Client visual stages are independently validated and their selection clamped. The BlockEntity now syncs exact growth age and total stage count to the client renderer, enabling more than eight distinct visual frames; the blockstate still retains eight model stages. Legacy or out-of-range saved age metadata is repaired on server chunk load, with a random-tick fallback if the crop catalogue was not available at load time. See `../temporary-research/LEGACY_CROP_STAGE_CHUNK_LOAD_MIGRATION.md`. See `../temporary-research/AGRIPLANTS_PARSER_VISUAL_STAGE_LIMITS.md` and `../temporary-research/EXACT_CROP_STAGE_CLIENT_SYNC.md`.
- Operator-only server command: `/cropgenetics data [summary|errors [page]|all [page]|tags [page]]` displays the latest datapack report and can inspect actually bound soil-tag membership from the live block registry (eight lines per page). Requires permission level 2 and also works from the server console. See `../temporary-research/CROP_DATAPACK_COMMAND.md` and `../temporary-research/RUNTIME_SOIL_TAG_AND_CLIENT_RESOURCE_SNAPSHOT.md`.
- AgriPlants-compatible server datapack definitions for wheat, carrot, potato, beetroot, nether wart, **melon and pumpkin**, plus five new Vanilla crop-stick species (cornflower, poppy, dandelion, cactus, sugar cane) and a carrot species mutation. Cactus/sugar cane currently approximate Vanilla growth rules; special block adapters remain future work.
- **Client-side resource-pack crop renderer**: custom BlockEntityRenderer draws crop texture overlays keyed by Genome.plantId and BlockState.STAGE. A client reload listener reads `assets/<namespace>/cropgenetics/plant_visuals/*.json`. Included visuals for wheat/carrots/potatoes/beetroot/nether wart; unknown species use a fallback texture. The client visual loader supports `cross`, `plus`, and approximated `gourd` geometry; visuals and missing-PNG warnings now publish as one client resource snapshot. Plant quads now sample sprites from the Minecraft block atlas, and `assets/minecraft/atlases/blocks.json` declares `textures/plant/` atlas sources. Physical gourd fruits use their own block models, not the old virtual fruit texture. Selected old AgriPlants `texture.plant_textures` entries can also be loaded if mirrored as client resources.

- Original AgriCraft asset reuse: wooden crop-stick block/item textures, legacy melon/pumpkin frames as **optional assets**, and the original magnifying-glass analyzer icon are retained. Vanilla plants, including melons and pumpkins, use Minecraft sprites by default. The original MIT license is retained at `LICENSE`. See `../temporary-research/ORIGINAL_AGRICRAFT_TEXTURES_PORT.md`.

## Crafting-only recovery of original seeds

One `cropgenetics:genetic_seed` **plus one paper** in any two crafting slots (2x2 inventory or 3x3 crafting table) yields exactly one plain original Minecraft/mod seed. The genetic seed is consumed; **the paper is returned as the crafting remainder** and is reusable. This is a special dynamic crafting recipe whose result is resolved from the seed's recorded `cropgenetics:original_seed` item ID, falling back to the current crop catalogue for older seeds. If the original item is unavailable or cannot be identified, the recipe does not match and nothing is consumed. There is no right-click recovery action. The returned plain seed intentionally loses all genetics and analysis data. See `src/main/java/dev/illedrabomb/cropgenetics/content/OriginalSeedRecoveryRecipe.java`. Source-only change; local crafting verification has not been performed.

## Vanilla visuals and analyzed genetic seed tooltips

Vanilla Minecraft textures remain the **default** for Vanilla species, including melon and pumpkin; the copied original AgriCraft gourd PNGs are optional assets rather than active replacements. The original AgriCraft crop-stick textures remain in use because Crop Sticks have no equivalent Vanilla asset.

Genetic seed stacks support a persistent `cropgenetics:analyzed` Boolean component. A playable `cropgenetics:seed_analyzer` is now registered (glass pane + stick), used from the main hand on an offhand seed. Existing alleles are preserved; unmodified registry-matched Vanilla seeds receive the established 1/1/1 baseline before being marked analyzed. Shift reveals Growth/Gain/Strength and Fertility/Mutativity alleles. The crop BlockEntity now also persists `SeedAnalyzed` and `OriginalSeed`, restoring them to the genetic seed when uprooted; new crossbreeding offspring start unanalyzed. If a locally developed analyzer already exists, compare and merge rather than duplicating item registrations. See `../temporary-research/VANILLA_TEXTURE_PRIORITY_AND_ANALYZED_SEED_SHIFT.md` and `../temporary-research/ANALYZER_GENOME_PRESERVATION_AND_FIVE_PLANTS.md`.

## Important data locations
- Server: `data/<namespace>/cropgenetics/plants/*.json`
- Server: `data/<namespace>/cropgenetics/mutations/*.json`
- Client: `assets/<namespace>/cropgenetics/plant_visuals/*.json`
- See `../temporary-research/DATA_DRIVEN_PLANT_RENDERER.md` and `../temporary-research/VANILLA_MOD_SEED_CONVERSION.md` for exact schema and tradeoffs.

The original AgriPlants directories are not automatically imported. Legacy soil chemistry, complex mutation predicates, special drops, model rendering, and modded crop hooks require dedicated migrations/adapters. The client visuals are **not automatically synchronized from server datapacks**.

## Five-workstream gameplay reliability update (2026-11-15)
The following source-only improvements are committed together: a staggered server BlockEntity ticker reconciles live crop stage metadata after datapack reload even with random ticks disabled; right-click harvest reconciles age before eligibility checking while block loot stays read-only; crossbreeding filters mutation species by actual destination soil and prefers a viable parent species if necessary; duplicate client visual species IDs are disabled with a predictable fallback; melon/pumpkin fruit placement now requires successful binding to an adjacent loaded parent crop. See `../temporary-research/CORE_GAMEPLAY_FIVE_WORKSTREAMS_2026_11_15.md`. **No builds or tests have run for these changes.** Ticker performance, API compilation, client visuals and fruit loot remain unverified.

## Legacy cactus contact adapter (source-only, 2026-11-16)
The cactus server definition now enables `cropgenetics_contact_thorns`. A planted thorny species deals Vanilla cactus contact damage server-side via `CropSticksBlock.entityInside`; empty crop sticks are not hazardous. The offline AgriPlants importer can translate exactly `agricraft:thorns` with explicit manifest option `adapt_thorns: true`. Direct unsupported legacy callbacks are still rejected. See `../docs/CACTUS_THORNS_ADAPTER.md`. This adapter does **not** port cactus climate, greenhouse generation or special asset behavior. **No builds or tests have been run for this change.**

## Biome and dimension location rules (source-only, 2026-11-16)
Crop datapacks can now optionally list exact allowed/blocked biome and dimension IDs. These restrictions affect planting, growth and crossbreeding in addition to the existing soil/light conditions. Mutations may specify independent location restrictions. Empty lists preserve existing behavior. The controlled AgriPlants migration tool accepts explicit 1.21.1 list mappings but does not infer them from legacy blacklist/Strength rules. See `../docs/BIOME_DIMENSION_CROP_MUTATION_RULES.md`. **No builds or game tests have run for these additions; legacy chemistry and seasonal rules remain unsupported.**

## Optional fluid and altitude rules (source-only, 2026-11-16)
Plant and mutation definitions now support inclusive crop-position `min_y` / `max_y` and an exact `fluid_id` registry match; mutations use the `cropgenetics_` field prefix. These filters apply to planting, growth and crossbreeding without changing existing definitions when unset. The server datapack validation now rejects unknown fluid references. The migration importer accepts explicit manifest mapping only, and **does not translate original AgriPlants fluid predicates**. No waterlogging, aquatic crop adapter, seasonal integration or soil chemistry is implied. See `../docs/FLUID_HEIGHT_ENVIRONMENT_RULES.md`. **Not built or tested.**

## Optional seasonal crop rules (source-only, 2026-11-16)
The core now accepts `allowed_seasons` in crop requirements and `cropgenetics_allowed_seasons` in mutations. A `SeasonAccess.Provider` supplies server-side season readings only when a separate, compatible integration has installed it. **No built-in seasonal calendar, no mandatory seasons mod, and no Serene Seasons adapter is connected yet.** When no provider is installed, seasonal restrictions are intentionally inactive. When an installed provider cannot determine the season, a season-restricted crop or mutation does not match. See `../docs/OPTIONAL_SEASONS_ARCHITECTURE.md` for behavior and separate soil-chemistry planning. **Not built or tested.**

## Opt-in soil chemistry profiles (source-only, 2026-11-16)
Plants and mutations can specify qualitative humidity, acidity and nutrient conditions using `soil_chemistry` / `cropgenetics_soil_chemistry`. A server-side provider reads explicit, **static per-block** soil profiles from optional datapacks at `data/<namespace>/cropgenetics/soil_profiles/*.json`. The core does **not** ship any soil profiles, invent vanilla farmland chemistry, or interpret original AgriCraft `tolerance_factor` formulas. Configured chemistry without a matching soil profile blocks growth or mutation; plants without chemistry rules work as before. Invalid and conflicting profiles are excluded during datapack reload. Details and example schema: `../docs/SOIL_CHEMISTRY_ARCHITECTURE.md`. **Not built or tested.**

## Persisted per-position soil chemistry (source-only, 2026-11-16)
In addition to static datapack soil profiles, `SoilOverrideSavedData` stores explicit qualitative values per soil block position and dimension using Minecraft 1.21.1 `SavedData`. Saved overrides take precedence over block-type profiles and are discarded on the next sample if the block ID has changed. Administrators (permission level 2) can inspect and edit loaded positions using `/cropgenetics soil show <x y z>`, `set <x y z> <humidity> <acidity> <nutrients>`, and `clear <x y z>`. No automatic irrigation, fertilizer, weather, or nutrient consumption rules have been added. Details: `../docs/DYNAMIC_SOIL_CHEMISTRY.md`. **Not built or tested.**

## First opt-in soil-care item actions (source-only, 2026-11-16)
Using a water bucket on crop sticks now requests a +1 humidity treatment for the soil directly beneath; bone meal requests +1 nutrient level. Only explicitly configured soil profiles or existing persistent overrides can be modified; there are no implicit vanilla soil chemistry defaults. When an actual change is saved, water bucket becomes an empty bucket or one bone meal is consumed, unless creative mode. Soil changes reuse the dimension-specific persisted overrides. This is **not** automatic irrigation, rain/fertilizer simulation, or AgriCore's historical tolerance model. See `../docs/SOIL_TREATMENTS.md`. **The interaction priority, consumption and behavior are not yet built or tested in-game.**

## AgriCraft 1.18 soil scales, Strength tolerance and first soil evolution (2026-11-16)
The official AgriCraft 1.18 docs list **6 humidity / 7 acidity / 6 nutrient** categories, and the soil requirement tolerance `requiredValue +/- tolerance_factor * expressedStrength`. The new `SoilChemistryRule` now models these categories and a bounded optional `tolerance_factor`, using the inherited Strength for offspring and mutations. Saved early NeoForge values `normal` and `saturated` remain readable via documented compatibility aliases. `SoilDynamics` also uses rain random ticks (1/16 chance) to increase humidity of explicitly profiled soil, and successful crop-stage growth (1/8 chance) to decrease nutrients. These tick chances are **new port design defaults, not AgriCraft-equivalent rules**; no vanilla chemistry is inferred without a datapack profile or saved override. See `../docs/AGRICORE_SOIL_PARITY_AND_EVOLUTION.md` and the official original soil docs linked there. **Uncompiled and untested**.

## Imported AgriPlants soil profiles and configurable dynamics (source-only, 2026-11-16)
Eight explicit vanilla block profiles from pinned AgriPlants 1.18.2 data now ship with the mod: farmland, sand, red sand, clay, podzol, mycelium, soul sand and soul soil. The historic `forge:sand` tag is represented only by the two listed vanilla IDs pending proper tag support. Each profile supplies original humidity, acidity, nutrients and `growth_modifier`; the latter multiplies `CropConditions.growthFactor` and affects crop stages and gourd fruit chances. Player-created chemistry overrides do not change the static block growth multiplier. Rain and growth nutrient depletion probabilities are set through `data/cropgenetics/cropgenetics/soil_dynamics.json` with `rain_tick_chance` and `growth_nutrient_chance` (0 disables; otherwise 1/N, defaults 16 and 8). These dynamics chances are port-specific, not historical AgriCore values. See `../docs/ORIGINAL_SOIL_PROFILES_AND_DYNAMICS_CONFIG.md` for source values, limits, overrides and compatibility notes. **Not built or tested.** Older README sections stating no profiles are bundled describe earlier iterations and are superseded by this section.

## Soil block tags and deferred block-edit invalidation (source-only, 2026-11-16)
Soil profile resources now accept **either** an exact `block` ID **or** a `block_tag`. Exact block profiles have precedence; ambiguous tag membership with multiple matching profile tags returns no sample rather than arbitrarily picking one. A bundled `c:sands` common-block-tag profile extends the historical sand soil profile to tagged modded blocks. Existing exact sand and red sand profiles remain. `SoilOverrideInvalidation` watches NeoForge player-break and entity-place events and reconciles saved positional chemistry overrides after the level tick, ignoring canceled events. This is **not** comprehensive for commands, explosions, pistons or arbitrary mod world edits. See `../docs/SOIL_TAGS_AND_BLOCK_INVALIDATION.md`. **Not compiled or tested**; `entwicklung`, `testing` and `master` are unchanged.

## Optional Farmer's Delight soil compatibility (source-only, 2026-11-16)
The soil profile loader now supports an optional `required_mod` ID: missing optional mods cause only their profiles to be skipped before block-registry validation. Two profiles imported from pinned AgriPlants 1.18.2 data target `farmersdelight:rich_soil` and `farmersdelight:rich_soil_farmland` with their original chemistry and `growth_modifier: 1.8`. No mandatory runtime Java dependency has been added. Presence of the soil profile does **not** automatically satisfy a plant's explicit `soil_block`/`soil_tag` planting restrictions. The exact Farmer's Delight NeoForge 1.21.1 block IDs and gameplay interactions still require verification. Existing block-change invalidation deliberately remains partial until an authoritative matching NeoForge event or block-update API is confirmed. Details: `../docs/OPTIONAL_FARMERS_DELIGHT_SOILS.md`. **Not built or tested.**

## Pam's HarvestCraft 2 priority — optional crop-sticks species (source-only, 2026-11-16)
Pam's HarvestCraft 2 compatibility is now prioritized above Farmer's Delight. Official downloads list NeoForge 1.21.1 builds for **Crops** (`pamhc2crops`), **Trees** and **Food Core**. Eight independently authored server datapack definitions derived from pinned AgriPlants 1.18.2 plant facts have been added for tomato, corn, rice, oats, rye, onion, cabbage and cotton at `data/cropgenetics/cropgenetics/plants/pamhc2_*.json`. They load **only when `pamhc2crops` is present**, and their original item IDs are checked during datapack reload. Normal Pam's planting is untouched; crop sticks are an additional planting route. Original seasonal/soil chemistry requirements are carried over to the modern explicit schema, but legacy `overridePlanting`, light/empty-fluid edge cases, textures, Pam's trees and mutation recipes need separate adapters. No Pam's copyrighted textures or models were copied. See `../docs/PAMS_HARVESTCRAFT_2_COMPATIBILITY.md`. **Not built or tested**. `entwicklung`, `testing`, and `master` remain unchanged.
